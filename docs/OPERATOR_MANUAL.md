## 1. 시스템 개요

### 1.1 서비스 소개

AI PAJAK은 인도네시아 세금 신고를 AI로 자동화하는 플랫폼입니다.

- **URL**: https://ai-pajak.vercel.app
- **지원 언어**: 한국어, English, Bahasa Indonesia, 日本語, 中文
- **지원 브라우저**: Chrome, Firefox, Safari, Edge (최신 버전)

### 1.2 주요 기능

| 기능 | 설명 |
|------|------|
| SPT 자동 생성 | OCR로 급여명세서 읽기 → SPT 1770SS/S/1770/1771 자동 작성 |
| AI 챗봇 | 인도네시아 세법 질의응답 (5개 언어 지원) |
| 월간 납부 관리 | PPh 21/23/25, PPN, PPh Final 월별 추적 |
| 절세 분석 | AI가 합법적 절세 기회 제안 |
| 이상 징후 감지 | 세무 조사 위험도 분석 |
| 컨설턴트 마켓플레이스 | 고객이 세무 컨설턴트 검색/연결 |
| 상담사 대기열 | DJP 수작업 제출 워크플로우 (Phase 1) |

### 1.3 시스템 아키텍처

```
[사용자 브라우저]
      ↓
[Vercel (Next.js 16)]  ←→  [Supabase (PostgreSQL + Auth)]
      ↓                           ↓
[Anthropic Claude API]     [Midtrans (결제)]
      ↓
[DJP API (인도네시아 국세청)]
```

## 2. 역할 및 권한

### 2.1 역할 체계

| 역할 | 코드 | 설명 | 접근 범위 |
|------|------|------|----------|
| **납세자** | CUSTOMER | 개인/법인 납세자 | 본인 세금 데이터만 |
| **컨설턴트** | CONSULTANT_JTC | JTC 소속 세무 컨설턴트 | 담당 고객 데이터 (계산/초안만) |
| **세무사** | TAX_ADVISOR_JTC | JTC 소속 공인 세무사 | 담당 고객 + DJP 신고 제출 |
| **상담사** | TAX_OPERATOR | DJP 수작업 제출 담당 | 배정된 고객 제출 대기열 |
| **상담 리더** | TAX_OPERATOR_LEAD | 상담사 팀 리더 | 전체 고객 + 재배정 |
| **상담 관리자** | TAX_OPERATOR_SUPERVISOR | 상담 운영 총괄 | 전체 + 상담사 관리 |
| **관리자** | PLATFORM_ADMIN | 플랫폼 관리자 | 시스템 관리 (세금 데이터 접근 **불가**) |

### 2.2 역할별 메뉴 접근 권한

```
CUSTOMER        : 대시보드, SPT 신고, 세금도구, 월간납부, 문서, 보고서, 설정, 도움말, 빌링
CONSULTANT_JTC  : 대시보드, 고객관리, 신고, SPT, 이상징후, 보고서, 절세분석, 세금도구
TAX_ADVISOR_JTC : 컨설턴트 기능 + DJP 제출, 일괄신고, POA 서명
TAX_OPERATOR    : 상담원 대시보드, 제출 대기열, 담당 고객, 세금 캘린더
PLATFORM_ADMIN  : 모니터링, 사용자관리, 결제관리, 컨설턴트관리, AI사용량, 감사로그, 세율관리
```

### 2.3 역할 전환

한 사용자에게 여러 역할이 부여된 경우, 사이드바에서 역할 전환이 가능합니다.

1. 사이드바 상단 역할 뱃지 확인
2. 아래 "○○로 전환" 버튼 클릭
3. 자동으로 해당 역할의 대시보드로 이동

## 3. 관리자 매뉴얼

### 3.1 사용자 관리

**경로**: 사이드바 → Admin → 사용자 관리

#### 사용자 등록

1. 우측 상단 **"사용자 등록"** 버튼 클릭
2. 필수 정보 입력:
   - **이메일**: 로그인용 이메일 주소
   - **비밀번호**: 최소 8자 (대소문자+숫자+특수문자 권장)
   - **역할**: 드롭다운에서 선택
3. 선택 정보 입력:
   - **이름**: 사용자 표시 이름
   - **NPWP**: 납세자 번호 (CUSTOMER 역할 시)
4. **"등록"** 클릭

| 역할 선택 시 | 자동 생성되는 항목 |
|-------------|-------------------|
| Customer | customer 프로필 (이름, NPWP) |
| Tax Operator | operator 프로필 (사원번호, 이름) |
| Tax Operator Lead | operator 프로필 (리더 권한) |
| Tax Operator Supervisor | operator 프로필 (관리자 권한) |
| 기타 역할 | 기본 계정만 |

#### 사용자 관리 작업

| 작업 | 방법 |
|------|------|
| **검색** | 상단 검색창에 이메일/이름/NPWP 입력 |
| **역할 필터** | 드롭다운에서 역할 선택 |
| **역할 변경** | 사용자 행 클릭 → 역할 드롭다운 변경 |
| **비밀번호 초기화** | 사용자 펼치기 → "비밀번호 초기화" 클릭 |
| **비활성화** | 사용자 펼치기 → "비활성화" 클릭 (로그인 차단) |
| **활성화** | 비활성 사용자 → "활성화" 클릭 |

### 3.2 시스템 모니터링

**경로**: 사이드바 → Admin → 모니터링

| 항목 | 정상 범위 | 주의 필요 |
|------|----------|----------|
| System Status | Operational (녹색) | Degraded/Down |
| Uptime | - | 재시작 직후 0 |
| DB Latency | < 200ms | > 500ms |
| Services | 모두 Operational | 하나라도 Down |
| Circuit Breakers | 모두 Closed | Open/Half-Open |
| Memory | < 80% | > 90% |

**자동 새로고침**: 30초마다 갱신. "Refresh" 버튼으로 수동 갱신 가능.

### 3.3 결제 관리

**경로**: 사이드바 → Admin → 결제 관리

**Overview 탭**:
- Total Revenue: 누적 매출
- MRR: 월간 반복 매출
- ARPU: 사용자당 평균 매출
- Active Subs: 활성 구독 수
- 거래 상태별 건수 (Paid/Pending/Failed)
- 플랜 분포

**거래 탭**:
- 전체 거래 내역
- 환불 처리: PAID 상태 거래의 "Refund" 클릭

### 3.4 컨설턴트 관리

**경로**: 사이드바 → Admin → 컨설턴트 관리

| 작업 | 방법 |
|------|------|
| 컨설턴트 검색 | 이메일 또는 법인명으로 검색 |
| 라이선스 편집 | Tax Advisor의 "License" 클릭 → 번호 입력 → ✓ |
| 비활성화 | "비활성화" 클릭 (로그인은 가능, 업무 차단) |
| 활성화 | "활성화" 클릭 |

### 3.5 AI 사용량 관리

**경로**: 사이드바 → Admin → AI 사용량

각 AI 기능별 Rate Limit 설정:

| AI 기능 | 기본 한도 | 단위 |
|---------|----------|------|
| AI Chatbot | 20회 | /시간/사용자 |
| OCR (문서) | 10회 | /시간/사용자 |
| AI 보고서 | 5회 | /일/사용자 |
| 세금 분석 | 10회 | /시간/사용자 |
| SPT 검증 | 20회 | /시간/사용자 |
| 이상 감지 | 10회 | /시간/사용자 |
| AI 일반 | 100회 | /일/사용자 |

**한도 변경**: "변경" 클릭 → 숫자 수정 → 저장 아이콘 클릭

> **주의**: Rate limit 변경은 즉시 적용됩니다. 너무 낮게 설정하면 사용자 경험에 영향을 줄 수 있습니다. 서버 재시작 시 기본값으로 복원됩니다.

### 3.6 감사 로그

**경로**: 사이드바 → Admin → 감사 로그

모든 세금 관련 활동이 자동 기록됩니다. **로그는 변경/삭제 불가** (Hard Rule #5).

| 필터 | 옵션 |
|------|------|
| 활동 유형 | Filing Create/Submit/Approve/Reject, POA Create/Sign/Revoke, Tax Calculation |
| 역할 | Customer, Consultant, Tax Advisor, Admin, System |

**로그 상세 확인**: 로그 행 클릭 → Log ID, Actor ID, IP Address, User Agent, Details JSON 표시

### 3.7 세율 관리

**경로**: 사이드바 → Admin → 세율 관리

인도네시아 세율을 카테고리별로 조회/편집합니다.

| 카테고리 | 예시 |
|---------|------|
| PPH21_BRACKET | 5%, 15%, 25%, 30%, 35% 누진세율 |
| PPH23 | 배당 15%, 서비스 2% |
| PTKP | TK/0: 54,000,000 등 12종 |
| PPN | 11% |
| PPH_FINAL | UMKM 0.5% |
| CORPORATE | 22%, UMKM 11% |

**편집 방법**:
1. 카테고리 필터에서 선택
2. 편집할 행의 ⚙️ 아이콘 클릭
3. 세율/금액/기준 수정
4. 💾 저장 클릭

> **주의**: 세율 변경은 새 계산에만 적용됩니다. 기존 계산은 변경되지 않습니다.

## 4. 상담사 매뉴얼

### 4.1 상담사 역할

Phase 1 (DJP API 연동 전)에서 상담사는 고객 대신 DJP 웹사이트에 수작업으로 세금 신고를 제출합니다.

```
[고객 데이터 입력] → [AI 계산] → [상담사 검토] → [e-Billing 생성]
→ [납부 확인] → [DJP 수작업 제출] → [BPE 업로드] → [완료]
```

### 4.2 상담원 대시보드

**경로**: 사이드바 → 상담원 대시보드

| KPI | 설명 |
|-----|------|
| 담당 고객 | 배정된 고객 수 (최대 35명) |
| 대기 건 | PENDING 상태 건수 |
| 진행 중 | DATA_REVIEW ~ BPE_UPLOADED 건수 |
| 완료 | 이번 달 COMPLETED 건수 |

하단에 대기열 요약 테이블이 표시됩니다.

### 4.3 제출 대기열 (워크플로우)

**경로**: 사이드바 → 제출 대기열

#### 상태 흐름도

```
PENDING → DATA_REVIEW → EBILLING_GENERATED → PAYMENT_CONFIRMED
→ DJP_SUBMITTED → BPE_UPLOADED → COMPLETED
                                          ↘ FAILED (어느 단계에서든 가능)
```

#### 각 단계별 작업

| 단계 | 상태 | 상담사 작업 | 버튼 |
|------|------|-----------|------|
| 1 | PENDING | 고객 데이터 완성도 확인 | "검토 시작" |
| 2 | DATA_REVIEW | 데이터 검증 후 e-Billing 코드 생성 | "e-Billing 생성" |
| 3 | EBILLING_GENERATED | 고객에게 납부 안내, 납부 확인 | "납부 확인" |
| 4 | PAYMENT_CONFIRMED | DJP 웹사이트에서 수작업 제출 | "DJP 제출" |
| 5 | DJP_SUBMITTED | DJP에서 BPE 다운로드 | "BPE 업로드" |
| 6 | BPE_UPLOADED | 최종 확인 | "완료" |

#### e-Billing 생성 (단계 2)

1. DATA_REVIEW 상태의 항목 확인
2. DJP e-Billing 시스템에서 코드 생성
3. "e-Billing 생성" 클릭
4. e-Billing 코드 입력 (예: `301234567890123`)
5. 확인

#### BPE 업로드 (단계 5)

1. DJP_SUBMITTED 상태의 항목 확인
2. DJP 웹사이트에서 BPE(Bukti Penerimaan Elektronik) 다운로드
3. "BPE 업로드" 클릭
4. BPE 번호 입력 (예: `BPE-2026-03-001`)
5. BPE 날짜 입력
6. 확인

#### 실패 처리

어느 단계에서든 문제 발생 시:
1. 해당 항목에서 "실패" 클릭
2. 실패 사유 입력
3. 확인 → 상태가 FAILED로 변경

#### 필터 사용

| 필터 | 옵션 |
|------|------|
| 상태 | 전체, PENDING, DATA_REVIEW, EBILLING_GENERATED, PAYMENT_CONFIRMED, DJP_SUBMITTED, BPE_UPLOADED, COMPLETED, FAILED |
| 세금 유형 | PPh21, PPh23, PPN, PPh_FINAL |
| 연도 | 2024, 2025, 2026 |
| 월 | 1~12 |

### 4.4 담당 고객

**경로**: 사이드바 → 담당 고객

배정된 고객 목록을 확인합니다.

| 표시 정보 | 설명 |
|----------|------|
| 고객명 | 회사명 또는 개인명 |
| NPWP | 납세자 번호 |
| 배정일 | 고객이 배정된 날짜 |
| 대기 건수 | PENDING~진행 중 건수 |
| 완료 건수 | COMPLETED 건수 |

검색: 고객명 또는 NPWP로 검색 가능

### 4.5 월간 워크플로우 타임라인

| 기간 | 작업 |
|------|------|
| 매월 1-10일 | 고객 데이터 수집 기간 (미입력 고객에게 자동 리마인더) |
| 매월 11일 | 상담원 검토 시작 |
| 매월 12-14일 | e-Billing 일괄 생성 |
| 매월 15일 | 고객 납부 확인 (PPh 납부 기한) |
| 매월 16-20일 | DJP 수작업 제출 |
| 매월 21일 | BPE 업로드 및 고객 알림 |

## 5. 컨설턴트/세무사 매뉴얼

### 5.1 고객 관리

**경로**: 사이드바 → 고객

| 기능 | 설명 |
|------|------|
| 고객 목록 | 담당 고객 전체 목록 |
| POA 상태 | ACTIVE/PENDING/EXPIRED/NONE |
| 검색/필터 | 이름, NPWP로 검색 |
| 대기 신고 | 미완료 신고 건수 |

### 5.2 고객 대신 SPT 작성

1. 사이드바 → 연간 신고
2. SPT 유형 선택 (1770SS/S/1770/1771)
3. 고객 선택 드롭다운에서 담당 고객 선택
4. 데이터 입력 또는 OCR 업로드
5. "SPT 생성" 클릭
6. 미리보기 확인 → PDF 다운로드

### 5.3 이상 징후 감지 (AI)

**경로**: 사이드바 → 이상 징후 감지

1. 고객 선택
2. AI 분석 대기 (10~30초)
3. 결과 확인:
   - **위험도**: LOW / MEDIUM / HIGH / CRITICAL
   - **카테고리**: 소득 변동, 공제 비율, 실효세율 등 9개
   - **감사 확률**: 세무 조사 가능성 %
   - **권고사항**: 각 항목별 대응 방안

### 5.4 고객 보고서 (AI)

**경로**: 사이드바 → 고객 보고서

1. 고객 선택
2. 연도 선택
3. "보고서 생성" 클릭
4. AI가 종합 보고서 작성:
   - 세금 현황 요약
   - 전년 대비 분석
   - 절세 기회
   - 위험 요소
   - 권고사항

### 5.5 컨설턴트 vs 세무사 차이

| 기능 | 컨설턴트 | 세무사 |
|------|---------|--------|
| 세금 계산 | ✅ | ✅ |
| SPT 초안 작성 | ✅ | ✅ |
| 이상 징후 감지 | ✅ | ✅ |
| 고객 보고서 | ✅ | ✅ |
| **DJP 제출** | ❌ | ✅ |
| **일괄 신고 (50건)** | ❌ | ✅ |
| **POA 서명** | ❌ | ✅ |

### 5.6 위임장(POA) 프로세스

```
[고객] POA 생성 (DRAFT)
  ↓
[고객] 서명 (PENDING_SIGNATURE)
  ↓
[세무사] 검토 + 서명 (ACTIVE)
  ↓
유효기간 만료 → EXPIRED
또는 취소 → REVOKED
```

## 7. 보안 규칙

### 7.1 6대 보안 규칙 (Hard Rules)

| # | 규칙 | 설명 | 위반 시 |
|---|------|------|---------|
| 1 | **관리자 ≠ 세금 데이터** | PLATFORM_ADMIN은 고객 세금 데이터 접근 불가 | API 403 차단 |
| 2 | **컨설턴트 ∈ JTC** | 컨설턴트는 반드시 JTC 소속 | FK 제약 위반 |
| 3 | **신고자 ≠ 플랫폼** | 세무사만 DJP 신고 제출 가능 | 역할 체크 차단 |
| 4 | **과금 ≠ 서비스** | 과금은 SYSTEM 역할만 | 역할 체크 차단 |
| 5 | **감사 로그 불변** | 모든 로그 INSERT only, 수정/삭제 불가 | DB 트리거 방지 |
| 6 | **POA 법적 인가** | 위임장 없이 고객 세금 신고 불가 | POA 미들웨어 차단 |

### 7.2 데이터 보호

- **RLS (Row Level Security)**: 47개 정책으로 행 수준 접근 제어
- **암호화**: 모든 통신 HTTPS (TLS 1.3)
- **인증**: Supabase Auth (JWT 기반)
- **세션**: 자동 갱신, 만료 시 재로그인

### 7.3 개인정보 처리

- NPWP, NIK 등 개인정보는 DB에 저장
- 관리자도 직접 조회 불가 (Hard Rule #1)
- 감사 로그로 모든 접근 기록

## 9. FAQ

### Q: 새 세율이 발표되면 어떻게 업데이트하나요?
**A**: Admin → 세율 관리에서 해당 세율을 찾아 인라인 편집합니다. 변경은 새 계산에만 적용됩니다.

### Q: 상담사에게 고객을 어떻게 배정하나요?
**A**: Supabase SQL Editor에서 `operator_client_assignments` 테이블에 INSERT하거나, 상담 리더/관리자가 API를 통해 배정합니다.

### Q: AI 챗봇이 잘못된 답변을 하면?
**A**: AI Rate Limit을 조정하거나, 시스템 프롬프트를 업데이트할 수 있습니다. 코드의 `src/app/api/chat/route.ts`에서 SYSTEM_PROMPT를 수정합니다.

### Q: DJP API 연동은 언제 전환되나요?
**A**: DJP ASP 인증 획득 후 Phase 2로 전환됩니다. 전환 시 상담사 역할은 모니터링으로 변경됩니다.

### Q: 사용자가 비밀번호를 잊었다면?
**A**: 두 가지 방법:
1. 로그인 페이지 → "비밀번호 찾기" (사용자 직접)
2. Admin → 사용자 관리 → "비밀번호 초기화" (관리자)

### Q: 한 사용자에게 여러 역할을 부여할 수 있나요?
**A**: 네. `user_roles` 테이블에 여러 행을 추가하면 사이드바에서 역할 전환 버튼이 표시됩니다.

### Q: 감사 로그를 삭제할 수 있나요?
**A**: 불가능합니다. Hard Rule #5에 따라 모든 감사 로그는 불변입니다. DB에서도 DELETE가 차단됩니다.

### Q: 서버 재시작 시 AI Rate Limit이 초기화되나요?
**A**: 현재 in-memory 저장이므로 재시작 시 기본값으로 복원됩니다. 영구 설정이 필요하면 DB 저장으로 전환해야 합니다.
