# AI Pajak 사업 제안서 (PRD)
### 인도네시아 납세자·중소기업을 위한 AI 기반 세무 신고 자동화 플랫폼

> **제출처**: 한국국제협력단(KOICA)
> **문서 성격**: ODA 사업 타당성 + 제품 요구사항 명세(PRD) 결합본
> **운영 주체**: Mono Flip Global / Jakarta Tax Consulting (JTC)
> **대상 국가**: 인도네시아 공화국
> **작성일**: 2026년 6월
> **버전**: 1.0

---

## 0. 요약 (Executive Summary)

AI Pajak는 인도네시아의 개인 납세자와 중소·영세기업(MSME)이 복잡한 세무 신고를 손쉽게 처리할 수 있도록 돕는 AI 기반 세무 신고 자동화 플랫폼이다. 인도네시아 세법(SPT 월·연 신고, 원천징수, 부가세)을 자동 계산하고, 영수증·인보이스를 광학문자인식(OCR)으로 입력하며, 인도네시아 국세청(DJP)의 신규 통합 세정 시스템 **Coretax**와 연동하여 전자납부(eBilling)·전자제출·전자접수증(BPE) 회수까지 끝-끝(end-to-end)으로 처리한다.

본 사업은 인도네시아의 만성적으로 낮은 조세부담률(GDP 대비 약 10%, 동급 중소득국 평균 대비 약 6%p 낮음)과 MSME의 낮은 세무 문해력(tax literacy) 문제를 디지털 공공 인프라(DPI) 관점에서 해결하고자 한다. 이는 SDG 8(양질의 일자리·경제성장), SDG 9(산업·혁신·인프라), SDG 16(효과적·투명한 제도), SDG 17(이행수단·파트너십)에 직접 기여하며, 한국의 전자정부·디지털 세정 경험을 인도네시아에 이전하는 한-인니 디지털 협력 모델이다.

플랫폼은 이미 프로덕션 단계(https://ai-pajak.vercel.app)에 도달해 있으며, 5개 언어(인도네시아어 기본, 영어·한국어·일본어·중국어)를 지원하고, 8개 사용자 역할과 다중 세무사무소(multi-tenant) 구조, 엄격한 데이터 격리·감사추적·보안 체계를 갖추고 있다.

## 1. 사업 배경 및 필요성

### 1.1 개발 문제 (Development Challenge)

인도네시아는 인구 2억 8천만 명, 동남아 최대 경제국이지만 조세 행정 측면에서 구조적 과제를 안고 있다.

- **낮은 조세부담률**: 2024년 기준 조세부담률(tax-to-GDP)은 약 10.08%로, 2022년 10.39%, 2023년 10.31%에서 오히려 하락 추세이며 세계은행은 2027년까지 10% 안팎에 머물 것으로 전망한다. 이는 유사 규모 중소득국 평균 대비 약 6%p 낮은 수준으로, 보건·교육·인프라 등 공공재 재원 확보를 제약한다.
- **MSME의 광범위한 비공식성**: 인도네시아 MSME는 전체 사업체의 약 99%, GDP의 약 61%, 고용의 약 97%를 차지하는 경제의 근간이다. 그러나 상당수가 비공식 부문에 머물러 있고, 낮은 세무 문해력·자원 부족·복잡한 규정으로 인해 정확한 신고에 어려움을 겪는다.
- **세정 디지털 전환의 과도기적 부담**: 인도네시아 국세청(DJP)은 2025년 1월 1일 통합 세정 시스템 **Coretax**를 전면 도입했고, 2025년 귀속분(2026년 신고)부터 Coretax 사용이 의무화된다. 시스템은 통합·실시간·투명성을 지향하지만, 새로운 워크플로우에 대한 납세자·영세사업자의 적응 부담이 크다는 점이 초기 도입 연구에서 반복적으로 지적되고 있다.

### 1.2 문제의 구조

세무 신고의 어려움은 단순히 "귀찮음"의 문제가 아니라 **정보 비대칭과 역량 격차**의 문제다. 대기업은 전문 세무팀과 회계법인을 보유하지만, 개인·영세사업자는 (1) 어떤 신고 양식이 적용되는지조차 모르고, (2) PTKP(기초공제)·세율·BPJS(사회보장)·UMKM Final(영세사업자 최종세) 등 계산 규칙이 복잡하며, (3) 종이 영수증을 디지털 데이터로 전환할 수단이 없고, (4) Coretax 전자제출 절차에 익숙하지 않다. 그 결과 미신고·과소신고·가산세 부담이 발생하고, 국가는 세수를, 사업자는 공식 금융 접근성(financial inclusion)을 잃는 악순환이 이어진다.

### 1.3 왜 지금, 왜 한국 ODA인가

한국은 홈택스(Hometax)·현금영수증·전자세금계산서 등 세계적 수준의 디지털 세정 인프라를 구축해 조세부담률과 납세 순응도를 크게 높인 경험이 있다. 인도네시아의 Coretax 전환기는 한국의 디지털 세정 노하우와 AI 기술을 이전할 최적의 시점이다. 본 사업은 정부 시스템을 대체하지 않고 **납세자와 DJP 사이의 "마지막 1마일"을 잇는 보완적 디지털 공공 인프라**로 설계되어, KOICA의 혁신적 기술 프로그램(CTS) 및 디지털 정부 협력 방향과 부합한다.

## 2. 사업 목표 및 개발 효과

### 2.1 상위 목표 (Goal)

인도네시아 개인·중소영세기업의 세무 신고 접근성과 정확성을 높여, **납세 순응도 제고 → 세수 기반 확대 → 공공재원 확충 → 포용적 성장**의 선순환에 기여한다.

### 2.2 사업 목적 (Purpose)

1. 복잡한 인도네시아 세법 계산을 자동화하여 비전문가도 정확한 신고가 가능하도록 한다.
2. OCR·AI로 영세사업자의 종이 기반 기록을 디지털 세무 데이터로 전환한다.
3. Coretax와의 연동으로 전자납부·전자제출·전자접수까지 원스톱으로 처리한다.
4. 세무 전문 인력(컨설턴트)의 생산성을 높여 서비스 단가를 낮추고 접근성을 확대한다.

### 2.3 산출물 (Outputs)

| 구분 | 산출물 |
|---|---|
| 시스템 | 프로덕션 수준의 다국어 세무 신고 플랫폼 (웹) |
| 자동화 모듈 | 월/연 신고·원천징수·부가세 계산 엔진, OCR 입력, Coretax 연동 |
| 역량 강화 | 5개 언어 사용자 매뉴얼, 역할별 시나리오 가이드, AI 세무 챗봇 |
| 생태계 | 다중 세무사무소(multi-tenant) 입점 구조, 영세사업자용 합리적 요금제 |

### 2.4 기대 개발 효과 (Outcomes & Impact)

- **재정**: 자발적 신고 증가를 통한 세수 기반 확대 (조세부담률 제고 기여)
- **포용**: 영세사업자의 공식 부문 진입 및 신용·금융 접근성 향상
- **거버넌스**: 감사추적·전자증빙으로 투명성과 책임성 강화 (반부패)
- **역량**: 디지털 세무 문해력 향상, 현지 세무서비스 인력 일자리 창출
- **젠더·형평**: 소규모 자영업·여성 사업자 등 취약 납세자의 진입장벽 완화

### 2.5 SDGs 연계

| SDG | 기여 내용 |
|---|---|
| **SDG 8** 양질의 일자리·경제성장 | MSME 공식화, 세무서비스 일자리, 생산성 향상 |
| **SDG 9** 산업·혁신·인프라 | 디지털 공공 인프라(DPI), AI 기술 이전 |
| **SDG 16** 평화·정의·제도 | 투명한 조세행정, 감사추적, 반부패 |
| **SDG 17** 이행수단·파트너십 | 한-인니 디지털 세정 협력, 민관 파트너십 |

## 3. 수혜 대상 (Beneficiaries)

### 3.1 직접 수혜자

- **개인 납세자 (INDIVIDUAL)**: 근로소득자, 자영업자 — 연 신고(1770SS/1770S/1770) 간소화
- **중소·영세 법인 (COMPANY)**: 월 신고·결산 부담을 자동화로 경감
- **현지 세무사무소 및 컨설턴트**: 입점형 ERP로 다수 고객을 효율적으로 관리, 생산성 향상

### 3.2 간접 수혜자

- **인도네시아 국세청(DJP)**: 신고 품질 향상, Coretax 보급 가속
- **인도네시아 정부·국민**: 세수 확대를 통한 공공서비스 재원
- **한국**: 디지털 세정 협력 레퍼런스 및 경제협력 기반 확대

### 3.3 포용성 고려

플랫폼은 인도네시아어를 기본 언어로 제공하고, 모바일 친화적 UI와 사진 기반 OCR 입력을 통해 PC·회계 지식이 부족한 영세사업자도 사용할 수 있도록 설계되었다. 결제는 영세사업자 단가(개인 SPT 건당 약 10만~30만 IDR)를 별도로 두어 비용 진입장벽을 낮춘다.

## 4. 제품 개요 및 핵심 기능 (Product Requirements)

### 4.1 제품 정의

AI Pajak는 **기술 플랫폼**이며, 세무 신고의 법적 주체는 제휴 세무사무소(JTC 및 외부 세무사무소)다. 플랫폼과 세무 서비스 제공 주체를 법적·구조적으로 분리하여 책임 소재를 명확히 한다.

### 4.2 핵심 기능 (Feature Set)

#### (1) 세무 자동 계산 엔진
- **월 신고 (SPT Masa)**: 원천징수 PPh 21·22·23·26·15·4(2), 부가가치세(PPN), 영세사업자 최종세(PPh Final 0.5%)
- **연 신고 (SPT Tahunan)**: 개인 1770SS·1770S·1770, 법인 1771(계산 엔진 보유)
- **자동 반영 규칙**: PTKP(기초공제), 누진세율(2024 개정), BPJS, 그로스업, 회계→세무 조정(koreksi fiskal)
- **연간 결산 워크플로우**: UMKM(0.5% 최종세) / PPh25(정상 법인세) 8단계 마감 — ID Billing 발급 → 납부 → DJP 제출 → BPE 수령 → 신고 완료

#### (2) OCR·AI 문서 처리
- Form 1721-A1, 세금계산서(Faktur Pajak), 인보이스 등을 사진/PDF에서 자동 추출·입력
- 인보이스 라인 단위 파싱(line-item), AI 파싱 실패 시 6단계 단계적 대체(graceful fallback)로 안정성 확보
- AI 세무 챗봇으로 납세자 질의 응대

#### (3) Coretax / DJP 연동
- 전자납부 코드(eBilling) 발급, Coretax 전자제출, 전자접수증(BPE) 자동 회수
- DJP API 장애 시 수동 모드 자동 전환(Circuit Breaker), 운영자 수기 입력 폴백

#### (4) 다중 세무사무소(Multi-tenant) 생태계
- JTC 내부 사무소 + 외부 세무사무소 입점, 사무소 간 데이터 완전 격리(RLS)
- 컨설턴트용 ERP(5단계 워크플로우 + 공동 거래처 DB + 리갈리티 자료 보관함)
- 팀장(Supervisor)용 집계·승인·품질관리 대시보드

#### (5) 운영팀 신고 처리 워크플로우
고객 "제출" 이후 운영팀이 데이터 검토 → 승인 → eBilling 발급 → 입금 확인 → DJP 제출 → BPE 업로드 → 완료까지 11단계 상태머신으로 처리, 모든 단계가 감사추적된다.

### 4.3 사용자 역할 (Roles)

| 역할 | 설명 |
|---|---|
| CUSTOMER (개인/법인) | 납세자 — 본인 데이터만 |
| CONSULTANT | JTC 또는 외부 사무소 컨설턴트 — 배정 고객만 |
| TAX_ADVISOR | 선임 세무사 — 신고 최종 제출 권한 |
| TAX_OPERATOR / SUPERVISOR / MASTER | 운영팀 (처리 / 승인·배분 / 플랫폼 통계·가격) |
| PLATFORM_ADMIN | 플랫폼 관리자 — **세무 데이터 접근 불가** |
| SYSTEM | 결제 자동화 전용 |

### 4.4 대표 사용자 시나리오

- **개인 근로소득자**: 로그인 → 적용 양식 자동 판별(1770SS) → 1721-A1 사진 업로드(OCR 자동입력) → 자동 계산 검토 → 제출 → 운영팀 처리 → BPE 수령
- **영세 자영업자**: 월 매출/매입 사진 업로드 → PPh Final 0.5% 자동 계산 → eBilling 납부 → 연말 결산 마감
- **현지 세무사무소**: 다수 고객을 ERP 보드에서 관리 → AI 파싱으로 자료 입력 시간 단축 → 팀장 승인 → Coretax 기록

## 5. 시스템 아키텍처 및 기술

### 5.1 기술 스택

| 영역 | 기술 |
|---|---|
| Framework | Next.js 16 (App Router) + React 19 + TypeScript(strict) |
| DB / Auth | Supabase (PostgreSQL + Auth + Row Level Security) |
| UI | shadcn/ui + Tailwind CSS 4 + Radix UI |
| 다국어 | next-intl — 5개 언어 (id 기본, en, ko, ja, zh) |
| AI / OCR | Anthropic SDK + OpenAI |
| 결제 | Midtrans (sandbox/production 명시 토글) |
| PDF | @react-pdf/renderer |
| 모니터링 | Sentry + pino 구조화 로깅 |
| 테스트 | Vitest(단위) + Playwright(E2E) |

### 5.2 회복력(Resilience) 설계

외부 시스템(DJP·결제·AI) 의존 구간에 **Circuit Breaker(장애 격리)**, **Idempotency Key(중복 방지)**, **Graceful Degrade(우아한 성능저하)**, **구조화 로깅·자동 에러 보고**를 적용하여, 외부 장애 시에도 데이터 유실 없이 복구 가능한 구조를 갖춘다. 이는 통신 환경이 불안정할 수 있는 현지 여건에서 특히 중요하다.

### 5.3 데이터 거버넌스·보안 (Non-functional Requirements)

플랫폼은 협상 불가능한 5대 보안 원칙을 데이터베이스(RLS)와 API(미들웨어) 두 계층에서 동시에 강제한다.

1. 플랫폼 관리자는 고객 세무 데이터에 접근할 수 없다.
2. 컨설턴트는 등록된 세무사무소에만 귀속되며, 사무소 간 데이터는 절대 교차되지 않는다.
3. 신고 제출 권한과 플랫폼 관리 권한은 분리된다.
4. 결제 처리 주체와 서비스 제공 주체는 분리된다.
5. 모든 쓰기 조치는 감사 로그에 자동 기록된다(7년 보존).

추가로 2단계 인증(TOTP), 행 단위 접근제어(RLS), 강력한 비밀번호 정책을 적용한다.

## 6. 사업 추진 계획 (Roadmap)

본 플랫폼은 이미 핵심 기능이 프로덕션에 배포된 상태이므로, KOICA 협력 사업은 **검증된 솔루션의 현지 확산·역량강화·지속가능성 확보**에 초점을 둔다.

| 단계 | 주요 활동 | 비고 |
|---|---|---|
| **1단계 (착수)** | 현지 수요조사, DJP·세무사무소 협력 MOU, 베이스라인 지표 측정 | 0~3개월 |
| **2단계 (현지화)** | Coretax 최신 연동 안정화, 현지어 콘텐츠·접근성 고도화, 파일럿 사무소 온보딩 | 3~9개월 |
| **3단계 (확산)** | 영세사업자 대상 보급, 세무 문해력 교육, 컨설턴트 역량강화 프로그램 | 9~18개월 |
| **4단계 (정착)** | 성과 평가, 지속가능 운영모델(요금/보조) 확립, 확장 로드맵 수립 | 18~24개월 |

## 7. 성과 측정 (M&E / KPI)

KOICA 성과관리 체계에 맞춰 정량·정성 지표를 설정한다. (구체 목표치는 베이스라인 측정 후 확정)

| 결과 수준 | 지표 (예시) |
|---|---|
| 산출(Output) | 누적 가입 납세자 수, 입점 세무사무소 수, 처리 신고 건수 |
| 성과(Outcome) | 신고 정확도(가산세 발생률 감소), 신고 소요시간 단축률, 재이용률 |
| 영향(Impact) | 대상 집단의 납세 순응도·공식화율 변화, 세무서비스 일자리 수 |
| 형평(Equity) | 영세·여성 사업자 이용 비율, 현지어 사용 비율 |

모든 핵심 트랜잭션이 감사 로그로 남으므로, 익명화된 집계 데이터를 통한 객관적 성과 측정과 외부 평가가 가능하다.

## 8. 지속가능성 및 위험관리

### 8.1 지속가능성

- **재무적**: 합리적 다층 요금제(개인 건당 / 법인 월구독 / 사무소 구독)로 운영비를 자체 충당하는 자립 모델. 영세 단가를 별도로 두어 접근성과 지속성을 동시에 확보.
- **제도적**: 현지 세무사무소 생태계에 입점형으로 안착하여, 사업 종료 후에도 현지 주체가 운영을 이어가는 구조.
- **기술적**: 검증된 오픈소스·클라우드 스택과 회복력 설계로 유지보수 부담 최소화.

### 8.2 주요 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| DJP/Coretax 정책·API 변경 | 연동 중단 | Circuit Breaker + 수동 모드 폴백, DJP 협력채널 |
| 낮은 디지털 문해력 | 보급 저조 | 현지어 매뉴얼·교육, AI 챗봇, 사진 기반 간편 입력 |
| 데이터 보안·프라이버시 | 신뢰 훼손 | 2계층 접근제어(RLS+미들웨어), 감사추적, 2FA |
| 결제 인프라 미비 | 수익 회수 지연 | Graceful Degrade, 다중 결제수단, 보류건 자동 재개 |

## 9. 결론

AI Pajak는 "디지털 세정 전환기의 인도네시아 영세 납세자"라는 명확한 개발 수요에, 이미 프로덕션에서 검증된 기술 솔루션으로 응답한다. 본 사업은 한국의 디지털 세정 경험과 AI 역량을 인도네시아에 이전하여, 납세 접근성과 정확성을 높이고 세수 기반과 경제 공식화를 동시에 촉진하는 **지속가능한 한-인니 디지털 공공 인프라 협력 모델**이다. KOICA의 혁신적 기술 협력 비전과 SDGs 이행에 직접 기여할 것이다.
