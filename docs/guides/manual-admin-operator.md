# Part A. PLATFORM_ADMIN 매뉴얼

PLATFORM_ADMIN은 AI Pajak 플랫폼의 운영 관리자입니다. 시스템 모니터링, 사용자/컨설턴트 관리, 청구/매출 확인, 세금 설정, 감사 로그 열람 등 플랫폼 전반의 관리 업무를 수행합니다.

> **중요**: PLATFORM_ADMIN은 고객의 세금 데이터(소득, 공제, 신고서 내용 등)에 접근할 수 없습니다. 이는 시스템의 가장 기본적인 보안 규칙(Hard Rule #1)이며, API 미들웨어와 데이터베이스 RLS 양쪽에서 이중으로 차단됩니다.

## A1. 대시보드 (플랫폼 통계)

**경로**: `https://aipajak.com/dashboard`

로그인 후 가장 먼저 표시되는 화면입니다. PLATFORM_ADMIN에게는 플랫폼 전체의 집계 통계가 표시됩니다.

### 표시 정보

| 항목 | 설명 |
|------|------|
| 총 사용자 수 | 역할별(CUSTOMER, CONSULTANT, TAX_ADVISOR 등) 사용자 수 |
| 활성 사용자 | 최근 활동이 있는 사용자 수 |
| 신고 현황 | 전체 신고 건수 집계 (익명화) |
| 매출 요약 | 월/주 단위 매출 추이 |

### 주의사항

- 모든 데이터는 **익명화된 집계**(aggregate) 형태로만 제공됩니다.
- 개별 고객의 이름, NPWP, 소득 정보 등 PII(개인식별정보)는 표시되지 않습니다.
- 대시보드 데이터는 실시간이 아닌 주기적 갱신 방식입니다.

## A2. 시스템 모니터링

**경로**: `https://aipajak.com/admin/monitoring`

플랫폼의 기술적 상태를 실시간으로 확인하는 화면입니다. **30초마다 자동 갱신**되며, 수동 새로고침도 가능합니다.

### 모니터링 항목

#### (1) 전체 시스템 상태

화면 상단에 시스템의 전체 상태가 뱃지로 표시됩니다.

| 상태 | 의미 | 색상 |
|------|------|------|
| Operational | 모든 서비스 정상 | 녹색 |
| Degraded | 일부 서비스 지연/장애 | 황색 |
| Down | 주요 서비스 중단 | 적색 |

추가로 버전, 환경(production/staging), 업타임(가동 시간)이 표시됩니다.

#### (2) 서비스 상태 (Services)

연동된 외부 서비스별 상태를 개별적으로 확인할 수 있습니다.

| 필드 | 설명 |
|------|------|
| 서비스명 | Supabase, Midtrans, DJP API, Resend 등 |
| 상태 | operational / degraded / down |
| 응답 시간 | ms 단위 레이턴시 |
| 마지막 확인 | 최종 헬스체크 시각 |

#### (3) Circuit Breaker 상태

외부 서비스 호출의 안정성을 보호하는 Circuit Breaker 패턴의 현재 상태입니다.

| 상태 | 의미 | 조치 |
|------|------|------|
| CLOSED | 정상 운영 중 | 조치 불필요 |
| OPEN | 장애 감지, 호출 차단 중 | 해당 서비스 상태 확인 필요 |
| HALF_OPEN | 복구 시도 중 (일부 호출 허용) | 모니터링 지속 |

실패 횟수(`failures`)와 마지막 실패 시각(`lastFailure`)도 표시됩니다.

#### (4) 메모리 사용량

| 필드 | 설명 |
|------|------|
| Heap Used | 실제 사용 중인 힙 메모리 |
| Heap Total | 할당된 전체 힙 메모리 |
| RSS | Resident Set Size (전체 프로세스 메모리) |
| 사용률(%) | 프로그레스 바로 시각화 |

#### (5) 에러 통계

| 구간 | 설명 |
|------|------|
| 최근 1시간 | 직전 1시간 내 발생 에러 수 |
| 최근 24시간 | 하루 동안의 에러 수 |
| 최근 7일 | 주간 에러 수 |

#### (6) 활동 추적 (Recent Audit Stats)

최근 감사 로그 기반 통계입니다.

| 필드 | 설명 |
|------|------|
| 총 액션 수 | 기록된 전체 활동 수 |
| Top Actions | 가장 빈번한 활동 유형과 횟수 |

### 대응 가이드

- **Circuit Breaker가 OPEN 상태인 경우**: 해당 외부 서비스(DJP, Midtrans 등)에 장애가 발생한 것입니다. 서비스 제공자의 상태 페이지를 확인하고, 자동 복구(HALF_OPEN 전환)를 기다리거나 개발팀에 알립니다.
- **메모리 사용률 80% 이상**: 서버 리소스가 부족할 수 있습니다. 개발팀에 스케일링을 요청합니다.
- **에러 급증**: 최근 1시간 에러 수가 비정상적으로 높으면 배포 이슈 또는 외부 서비스 장애를 의심합니다.

## A3. 사용자 관리

**경로**: `https://aipajak.com/admin/users`

플랫폼에 등록된 모든 사용자를 조회하고 관리합니다.

### 기능 목록

#### (1) 사용자 조회

- **검색**: 이메일 또는 이름으로 검색
- **역할별 필터**: CUSTOMER, CONSULTANT_JTC, TAX_ADVISOR_JTC, PLATFORM_ADMIN 등으로 필터링
- **통계 카드**: 전체 사용자 수, 역할별 분포, 활성/비활성 수

#### (2) 사용자 상세 정보

사용자 행을 클릭하면 확장되어 아래 정보를 확인할 수 있습니다.

| 필드 | 설명 |
|------|------|
| 이메일 | 등록 이메일 |
| 이름 | 사용자 풀 네임 |
| NPWP | 납세자번호 |
| 역할 | 현재 부여된 역할 |
| 계정 상태 | 활성(Active) / 비활성(Inactive) |
| 이메일 인증 | 인증 완료 여부 |
| 가입일 | 계정 생성 일시 |
| 마지막 로그인 | 최종 로그인 일시 |

#### (3) 사용자 관리 액션

| 액션 | 설명 |
|------|------|
| 역할 변경 | 사용자의 역할을 변경 (예: CUSTOMER에서 CONSULTANT_JTC로) |
| 계정 활성화/비활성화 | 계정 접근을 허용하거나 차단 |
| 비밀번호 초기화 | 임시 비밀번호 발급 |

#### (4) 사용자 생성

`+ 사용자 추가` 버튼으로 새 사용자를 직접 생성할 수 있습니다.

| 입력 필드 | 필수 여부 | 설명 |
|-----------|-----------|------|
| 이메일 | 필수 | 로그인에 사용 |
| 비밀번호 | 필수 | 초기 비밀번호 |
| 이름 | 필수 | 사용자 표시명 |
| 역할 | 필수 | 드롭다운에서 선택 |
| NPWP | 선택 | 납세자번호 |

> **주의**: 역할 변경 시 해당 사용자의 접근 권한이 즉시 변경됩니다. 특히 TAX_ADVISOR_JTC 역할은 세금 신고 제출 권한을 부여하므로 신중하게 설정하세요.

## A4. 컨설턴트 관리

**경로**: `https://aipajak.com/admin/consultants`

JTC(Jakarta Tax Consulting) 소속 컨설턴트와 세무사를 관리합니다.

### 통계 카드

| 항목 | 설명 |
|------|------|
| 전체 컨설턴트 수 | 등록된 총 컨설턴트 |
| 활성 컨설턴트 | 현재 활동 중인 컨설턴트 |
| 면허 보유 세무사 | TAX_ADVISOR_JTC 역할의 자격 보유자 |
| 전체 고객 수 | 컨설턴트에 배정된 고객 총수 |

### 관리 기능

| 기능 | 설명 |
|------|------|
| 검색 | 이메일 또는 법인명으로 검색 |
| 활성화/비활성화 | 컨설턴트의 활동 상태 전환 |
| 면허번호 등록/수정 | 세무사 면허번호 입력 및 변경 |
| 세무사 권한 부여 | Advisor 역할 활성화 |

### 표시 정보

각 컨설턴트 카드에는 다음 정보가 표시됩니다.

- **이메일**: 로그인 계정
- **소속 법인명**: JTC 소속 확인
- **활성 상태**: Active/Inactive 뱃지
- **세무사 여부**: Advisor 뱃지
- **면허번호**: 등록된 경우 표시
- **전문분야**: 등록된 specialization 태그
- **담당 고객 수**: 활성 고객 / 전체 고객
- **신고 건수**: 처리한 세금 신고 누적 건수

## A5. 청구/매출 관리

**경로**: `https://aipajak.com/admin/billing`

플랫폼의 수익과 거래를 관리합니다. **개요(Overview)**와 **거래 내역(Transactions)** 두 개의 탭으로 구성됩니다.

### (1) 개요 탭

매출 통계를 한눈에 확인할 수 있습니다.

| 항목 | 설명 |
|------|------|
| 총 매출 | 누적 매출 (Rp 단위) |
| 월 매출 | 이번 달 매출 |
| 활성 구독자 | 유료 플랜 구독 중인 사용자 수 |
| 구독 분포 | 플랜별 구독자 비율 |

### (2) 거래 내역 탭

개별 결제 거래를 조회합니다.

| 필드 | 설명 |
|------|------|
| 거래 ID | Midtrans 거래 고유번호 |
| 금액 | 결제 금액 (Rp) |
| 상태 | PAID / PENDING / FAILED / REFUNDED |
| 일시 | 거래 발생 일시 |

#### 거래 상태별 색상

| 상태 | 색상 | 설명 |
|------|------|------|
| PAID | 녹색 | 결제 완료 |
| PENDING | 황색 | 결제 대기 중 |
| FAILED | 적색 | 결제 실패 |
| REFUNDED | 회색 | 환불 완료 |

### (3) 환불 처리

거래 내역에서 PAID 상태의 거래에 대해 **환불** 버튼이 표시됩니다. 클릭하면 환불이 처리되고 상태가 REFUNDED로 변경됩니다.

> **주의**: 환불은 되돌릴 수 없습니다. 환불 실행 전 거래 내용을 충분히 확인하세요.

## A6. 세금 설정

세금 계산에 적용되는 세율, 규칙, 테스트 기능을 관리합니다. 3개의 하위 메뉴로 구성됩니다.

### A6-1. 세율 관리

**경로**: `https://aipajak.com/admin/tax-rates`

인도네시아 세법에 따른 세율 테이블을 조회하고 수정합니다.

#### 세율 카테고리

| 카테고리 | 설명 |
|----------|------|
| PPH21_BRACKET | 소득세 누진세율 구간 |
| PPH21_TER_A/B/C | PPh21 TER(Tarif Efektif Rata-rata) 세율표 |
| PPH23 | 원천징수세율 |
| PPH23_SERVICE | 서비스별 원천징수세율 |
| PPH42_CONSTRUCTION | 건설업 최종세 |
| PTKP | 비과세 기본공제액 |
| PPN | 부가가치세율 |
| PPH_FINAL | 최종분리과세 |
| CORPORATE | 법인세율 |
| PPH22 | 수입세 |
| NPWP_SURCHARGE | NPWP 미보유 가산세율 |
| LIMITS | 각종 한도 금액 |

#### 수정 가능 필드

| 필드 | 설명 |
|------|------|
| 세율(rate_value) | 백분율 세율 (소수점) |
| 금액(amount_value) | 고정 금액 (PTKP 등) |
| 최소 기준액(threshold_min) | 구간 하한 |
| 최대 기준액(threshold_max) | 구간 상한 |
| 라벨(label) | 표시명 |
| 법적 근거(legal_basis) | 관련 법조문 |

#### 수정 절차

1. 카테고리 목록에서 원하는 카테고리를 클릭합니다.
2. 해당 카테고리의 세율 항목들이 표시됩니다.
3. 수정하려는 항목의 **편집** 버튼을 클릭합니다.
4. 값을 변경한 후 **저장** 버튼을 클릭합니다.
5. 성공 메시지가 표시되면 저장 완료입니다.

> **주의**: 세율 변경은 이후 모든 세금 계산에 즉시 반영됩니다. 변경 전 반드시 법적 근거를 확인하고, 변경 후 Rule Test로 검증하세요.

### A6-2. Override Rule 관리

**경로**: `https://aipajak.com/admin/override-rules`

특수한 거래 조건에 대해 기본 세율 대신 적용할 예외 규칙을 관리합니다.

#### Override Rule 구조

| 구분 | 필드 | 설명 |
|------|------|------|
| **조건(Condition)** | 서비스 카테고리 | SERVICE, CONSTRUCTION, RENTAL, EMPLOYMENT, DIVIDEND, INTEREST, ROYALTY, IMPORT, SHIPPING, OTHER |
| | 수취인 유형 | RESIDENT (거주자) / NON_RESIDENT (비거주자) |
| | 벤더=대표 여부 | 벤더가 법인 대표인 경우 |
| | 특수관계자 여부 | 특수관계자 거래 여부 |
| | KBLI 패턴 | 업종코드 패턴 매칭 |
| | 국가 | 거래 상대방 국가 |
| **결과(Result)** | 세목 | PPh21, PPh23, PPh26, PPh4(2), PPh22, PPh15, PPN |
| | 세율 | 적용할 세율 |
| | 최종세 여부 | Final tax 여부 |
| | 적용 사유 | 규칙 적용 근거 설명 |
| | 법적 근거 | 관련 법조문 |
| **관리** | 우선순위 | 숫자가 낮을수록 우선 적용 |
| | 활성 상태 | 규칙 활성화/비활성화 |

#### 규칙 관리 절차

## A9. 보안 규칙 (5대 Hard Rule)

AI Pajak 플랫폼은 다음 5가지 보안 규칙을 시스템 수준에서 강제합니다. 이 규칙들은 코드에 하드코딩되어 있으며, API 미들웨어와 데이터베이스 RLS(Row Level Security) 양쪽에서 이중으로 적용됩니다.

### Hard Rule #1: PLATFORM_ADMIN은 고객 세금 데이터에 접근할 수 없다

| 항목 | 내용 |
|------|------|
| **규칙** | PLATFORM_ADMIN 역할의 사용자는 고객의 소득, 공제, 세금 신고서 등 세금 관련 데이터에 일체 접근할 수 없습니다. |
| **시행 방법** | `blockPlatformAdmin` 미들웨어가 모든 세금 데이터 API에 적용됩니다. 데이터베이스 RLS 정책도 PLATFORM_ADMIN의 세금 데이터 접근을 차단합니다. |
| **이유** | 세금 데이터는 고객의 민감한 재무 정보이며, 플랫폼 관리 업무와 분리되어야 합니다. 관리자가 고객 데이터에 접근하는 것은 이해충돌(conflict of interest)을 야기할 수 있습니다. |

### Hard Rule #2: 컨설턴트는 반드시 JTC 소속이어야 한다

| 항목 | 내용 |
|------|------|
| **규칙** | 모든 컨설턴트(CONSULTANT_JTC)는 Jakarta Tax Consulting(JTC) 조직에 소속되어야 합니다. |
| **시행 방법** | 데이터베이스 외래 키(FK) 제약조건과 RLS 정책으로 강제합니다. |
| **이유** | 세무 서비스의 품질과 책임 소재를 명확히 하기 위해 JTC 소속만 컨설턴트 활동이 허용됩니다. |

### Hard Rule #3: 세금 신고 제출은 TAX_ADVISOR_JTC만 가능하다

| 항목 | 내용 |
|------|------|
| **규칙** | 세금 신고서의 최종 제출(DJP 전송)은 TAX_ADVISOR_JTC 역할의 세무사만 수행할 수 있습니다. PLATFORM_ADMIN이나 일반 컨설턴트는 제출할 수 없습니다. |
| **시행 방법** | `requireRole(UserRole.TAX_ADVISOR_JTC)` 미들웨어로 API 수준에서 강제합니다. |
| **이유** | 인도네시아 세법상 세금 신고는 자격을 갖춘 세무 대리인만 수행할 수 있습니다. |

### Hard Rule #4: 과금 수행자와 서비스 제공자는 분리한다

| 항목 | 내용 |
|------|------|
| **규칙** | 청구/결제 처리(billing operations)는 SYSTEM 역할의 자동화 프로세스만 수행할 수 있습니다. 세무 서비스를 제공하는 사용자(TAX_ADVISOR_JTC 등)가 직접 과금을 수행할 수 없습니다. |
| **시행 방법** | `billingOperation()` 미들웨어 스택이 SYSTEM 역할만 허용합니다. |
| **이유** | 서비스 제공자와 과금 수행자를 분리하여 부정행위 및 이해충돌을 방지합니다. |

### Hard Rule #5: 모든 쓰기 작업에 감사 로그가 필수이다

| 항목 | 내용 |
|------|------|
| **규칙** | 데이터를 생성, 수정, 삭제하는 모든 API 작업은 감사 로그(audit trail)를 남겨야 합니다. |
| **시행 방법** | `withAudit('ACTION_NAME')` 미들웨어가 모든 쓰기 API에 포함됩니다. 미들웨어 없이는 API가 동작하지 않습니다. |
| **이유** | 규제 준수(compliance), 사고 추적, 책임 소재 확인을 위해 모든 활동 기록이 필수적입니다. |

# Part B. TAX_OPERATOR 매뉴얼

TAX_OPERATOR는 세금 신고서의 실무 처리를 담당하는 역할입니다. 고객의 신고 건을 대기열에서 가져와 검토하고, 각 단계를 진행하며, 최종 완료까지 이끕니다.

역할은 3단계로 나뉩니다.

| 역할 | 권한 범위 |
|------|-----------|
| TAX_OPERATOR | 기본 처리: 대기열 관리, 상태 전환, 고객 조회 |
| TAX_OPERATOR_LEAD | 기본 처리 + 업무 할당 관리 |
| TAX_OPERATOR_SUPERVISOR | 모든 권한 + 승인/반려, 통계, 민원 처리, 승인 규칙 설정 |

## B2. 신고서 처리 워크플로우

**경로**: `https://aipajak.com/operator/queue`

신고서 처리의 핵심 화면입니다. 전체 대기열을 조회하고 각 건의 상태를 전환합니다.

### 워크플로우 상태 전환도

```
PENDING
  |
  v
DATA_REVIEW
  |
  v
PENDING_APPROVAL  ---(반려)---> FAILED
  |
  v (Supervisor 승인)
APPROVED
  |
  v
EBILLING_GENERATED
  |
  v
PAYMENT_PENDING
  |
  v
PAYMENT_UPLOADED
  |
  v
PAYMENT_VERIFIED
  |
  v
DJP_SUBMITTED
  |
  v
BPE_UPLOADED
  |
  v
COMPLETED

* 모든 상태에서 FAILED로 전환 가능
```

### 각 상태별 상세 절차

#### (1) PENDING (대기)

- **의미**: 신규 신고 건이 대기열에 등록된 초기 상태
- **수행 액션**: `data_review` - 데이터 검토 시작
- **담당**: TAX_OPERATOR

#### (2) DATA_REVIEW (데이터 검토)

- **의미**: 운영자가 신고 데이터의 정확성을 검토하는 단계
- **수행 액션**: `submit_for_approval` - 검토 완료 후 승인 요청
- **담당**: TAX_OPERATOR
- **체크포인트**: 고객 정보, NPWP, 소득 내역, 공제 항목, 세액 계산 등을 확인

#### (3) PENDING_APPROVAL (승인 대기)

- **의미**: Supervisor의 승인을 기다리는 단계
- **수행 액션**:
  - `approve` - 승인 (Supervisor 전용)
  - `reject` - 반려 (Supervisor 전용, 반려 사유 입력 필수)
- **담당**: TAX_OPERATOR_SUPERVISOR

#### (4) APPROVED (승인 완료)

- **의미**: Supervisor가 승인한 상태
- **수행 액션**: `generate_ebilling` - e-Billing 코드 생성
- **담당**: TAX_OPERATOR

#### (5) EBILLING_GENERATED (e-Billing 생성 완료)

- **의미**: e-Billing 코드가 생성된 상태
- **수행 액션**: `payment_pending` - 납부 대기 전환
- **담당**: TAX_OPERATOR

#### (6) PAYMENT_PENDING (납부 대기)

- **의미**: 고객이 세금을 납부하기를 기다리는 상태
- **수행 액션**: `upload_payment` - 납부 영수증 업로드
- **담당**: TAX_OPERATOR

#### (7) PAYMENT_UPLOADED (납부 영수증 업로드)

- **의미**: 납부 영수증이 업로드된 상태
- **수행 액션**: `verify_payment` - 납부 확인
- **담당**: TAX_OPERATOR

#### (8) PAYMENT_VERIFIED (납부 확인 완료)

- **의미**: 납부가 확인된 상태
- **수행 액션**: `submit_djp` - DJP(세무서)에 전자 제출
- **담당**: TAX_OPERATOR

#### (9) DJP_SUBMITTED (DJP 제출 완료)

- **의미**: DJP에 전자 신고가 완료된 상태
- **수행 액션**: `upload_bpe` - BPE(접수증) 업로드
- **담당**: TAX_OPERATOR
- **입력 필드**: BPE 번호, BPE 일자

#### (10) BPE_UPLOADED (BPE 업로드 완료)

- **의미**: BPE가 업로드된 상태
- **수행 액션**: `complete` - 최종 완료 처리
- **담당**: TAX_OPERATOR

#### (11) COMPLETED (완료)

- **의미**: 모든 처리가 완료된 최종 상태
- **추가 액션 없음**

#### (12) FAILED (실패)

- **의미**: 처리 중 오류 발생 또는 Supervisor 반려
- **수행 액션**: `retry` - 재처리 (PENDING 상태로 복귀)
- **담당**: TAX_OPERATOR

### 대기열 필터링

| 필터 | 옵션 |
|------|------|
| 상태 | 12가지 상태 중 선택 |
| 세목 | PPh21, PPh23, PPh25, PPh29, PPN, SPT1770SS, SPT1770S, SPT1770 |

### 상태 전환 방법

1. 대기열에서 처리할 건을 찾습니다.
2. 해당 건의 **액션 버튼**을 클릭합니다. (현재 상태에 따라 버튼이 달라집니다.)
3. 필요한 경우 추가 정보를 입력합니다 (BPE 번호, 반려 사유 등).
4. 확인을 클릭하면 상태가 전환됩니다.
5. 페이지가 자동으로 새로고침되어 변경된 상태를 확인할 수 있습니다.

### B4-5. 승인 규칙 (Approval Rules)

**경로**: `https://aipajak.com/operator/approval-rules`

자동 승인 조건을 설정합니다. 조건을 충족하는 신고 건은 Supervisor의 수동 승인 없이 자동으로 승인됩니다.

#### 자동 승인 조건

| 파라미터 | 기본값 | 설명 |
|----------|--------|------|
| 최소 OCR 신뢰도 | 85% | OCR 인식 결과의 최소 신뢰도 |
| 최대 위험 점수 | 30 | 위험도가 이 값 이하여야 자동 승인 |
| 최소 준수 점수 | 75 | 규정 준수 점수 최소값 |
| 최소 검증 점수 | 85 | 데이터 유효성 점수 최소값 |
| 최소 신뢰 점수 | 70 | 종합 신뢰 점수 최소값 |
| 최대 자동 승인 금액 | Rp 10,000,000 | 이 금액 이하만 자동 승인 |
| 활성 상태 | ON | 자동 승인 기능 활성화 여부 |

#### 자동 승인 통계

| 항목 | 설명 |
|------|------|
| 전체 처리 건수 | 총 처리된 신고 건수 |
| 자동 승인 건수 | 규칙에 의해 자동 승인된 건수 |
| 수동 검토 대기 | 자동 승인 조건을 불충족하여 수동 검토가 필요한 건수 |
| 자동 승인률 | 자동 승인 비율 (%) |

#### 규칙 수정 절차

1. 각 파라미터의 값을 입력 필드에서 수정합니다.
2. **저장** 버튼을 클릭합니다.
3. 성공 메시지가 표시되면 적용 완료입니다.

> **주의**: 자동 승인 기준을 너무 느슨하게 설정하면 부정확한 신고가 자동 승인될 위험이 있습니다. 반대로 너무 엄격하면 대부분의 건이 수동 검토 대기 상태가 되어 업무 효율이 저하됩니다. 적정 수준을 유지하면서 자동 승인 통계를 모니터링하세요.
