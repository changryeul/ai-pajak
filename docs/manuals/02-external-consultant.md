# 외부 세무 사무소 매뉴얼

> **대상**: AI Pajak을 사용해 **여러 법인·개인 고객의 세무 신고를 대행**하는 **외부 세무 사무소**(Jakarta Tax Consulting 외의 다른 회계·세무 법인) 소속 컨설턴트·대표
>
> **한 줄 요약**: 본인 사무소의 고객을 격리된 공간에서 관리하고, 매월 구독료를 내며, 고객 수에 따라 Starter/Growth/Enterprise 3단계 요금제를 선택합니다.

## 1. AI Pajak은 외부 세무사무소에게 무엇을 제공하는가

기존에는 JTC 내부 세무사만 AI Pajak을 사용했지만, Phase B부터 **외부 세무 사무소**도 플랫폼에 합류할 수 있습니다. 외부 사무소는 다음을 얻습니다.

- **본인 사무소 전용 공간** — 귀 사무소의 고객은 JTC나 다른 사무소 직원에게 절대 보이지 않습니다 (RLS 격리)
- **고객 수에 맞춘 월 구독제** — 시작은 월 Rp1,000,000부터
- **다중 고객 일괄 처리** — Growth 플랜 이상에서 bulk PPh21, 월간 통합 대시보드
- **OCR·회계 연동·자동화** — JTC 내부 세무사와 동일한 기술 스택 사용
- **AI Pajak 결제·알림 인프라** — Midtrans, WhatsApp, 이메일 자동화 사용

결국 귀 사무소가 플랫폼을 **Tool**로 사용하고, AI Pajak(JTC)에는 **도구 사용료(Tool Fee)**만 지불하는 구조입니다. 고객에 대한 청구·소통은 귀 사무소가 **직접** 진행합니다.

## 2. 가입부터 첫 고객 등록까지

### 2.1. 사무소 가입
1. `https://ai-pajak.vercel.app/register` 접속
2. 사무소 대표 이메일로 가입
3. 회원가입 폼에서 **"외부 세무 사무소로 가입"** 체크
4. 사무소 정보 입력:
   - 사무소명 (상호)
   - NPWP Badan (법인 NPWP)
   - 주소, 전화
   - 대표자 성명
5. 가입 즉시 `CONSULTANT_JTC`와 유사한 권한이 부여되나, 내부적으로는 **EXTERNAL tax_partner** 로 구분됩니다.
6. 시스템이 자동으로 `tax_partner` 레코드(`partner_type = 'EXTERNAL'`)를 생성하고, 가입자를 그 사무소의 **대표 컨설턴트**로 등록합니다.

### 2.2. 첫 로그인 후 해야 할 일

| # | 위치 | 할 일 |
|---|---|---|
| 1 | **설정 → 사무소 프로필** | 사무소 상세 정보 보완 (로고, 연락처, 사업자번호) |
| 2 | **설정 → 보안** | 2FA 활성화 (고객 정보 접근 계정이므로 필수 권장) |
| 3 | **청구 → 컨설턴트 플랜** | Starter / Growth / Enterprise 중 선택 → Midtrans 결제 |
| 4 | **고객** → **신규 고객 추가** | 첫 고객 레코드 등록 |
| 5 | 선택 사항: **팀 관리** | 사무소 내 다른 직원 초대 (Growth 플랜 이상) |

### 2.3. 구독이 활성화되어야 모든 기능이 열립니다

구독 결제가 `ACTIVE` 상태가 되기 전까지는 **고객 추가와 신고 제출이 제한**됩니다. Tier 결제가 완료되면 다음이 해제됩니다.

- 고객 수 제한(Tier별 최대치까지)
- 신고 제출(JTC 운영팀 큐로 전송)
- 회계 연동, 문서 OCR, 일괄 처리

## 3. 대시보드와 사이드바

### 3.1. 외부 컨설턴트 대시보드
로그인 첫 화면에는 **내 고객 요약 카드**, **이번 달 미결 신고 현황**, **현재 Tier 상태(`ConsultantTierWidget`)**, **관리 고객 수 vs Tier 한도** 가 표시됩니다.

### 3.2. 사이드바 메뉴 (외부 컨설턴트)

**세무 작업**
- **대시보드**
- **뉴스** — 인도네시아 세법 업데이트
- **고객** (`/customers`) — **이 메뉴가 핵심** — 본인 사무소 고객만 목록에 나옵니다
- **월 대시보드** (`/tax/monthly-dashboard`) — 고객 × 신고 유형 교차표
- **월 신고 → PPh21 / PPh23 / UMKM / PPN** — 선택한 고객 기준
- **일괄 PPh21** (`/tax/pph21-bulk`) — 여러 고객의 급여를 한꺼번에 입력 (Growth 이상)
- **연간 정산 / 재무제표** — 고객별 연간 SPT 준비
- **제출현황** / **신고건** — 운영팀 큐 상태 확인

**도구**
- **인보이스 캡처**, **문서 업로드**, **세금달력**, **세금도구**

**사무소 관리**
- **청구 → 컨설턴트 플랜** — 현재 Tier, 업그레이드, 결제 이력
- **팀 관리** (`/admin/team`) — 소속 직원 초대·비활성화 (Growth 이상)
- **사무소 프로필**
- **통합설정** — 회계 소프트웨어 연동
- **설정** — 2FA, 알림, 언어

**중요**: 외부 컨설턴트는 "플랫폼 관리자" 메뉴(`/admin/*` 중 일부)에는 접근할 수 없습니다. **팀 관리** 만 본인 사무소 범위로 사용 가능합니다.

## 4. 핵심 플로우

### 4.1. 플로우 A — 신규 고객 등록하기

**전제**: 구독이 `ACTIVE` 이고 현재 Tier 한도에 여유가 있어야 합니다.

1. 사이드바 **고객 → 신규 고객 추가**
2. 고객 유형 선택 — **법인(COMPANY)** 또는 **개인(INDIVIDUAL)**
3. 기본 정보 입력 — 회사명 또는 성명, NPWP, 주소, 연락처, 담당자 이메일
4. **POA(위임장) 업로드** — 고객이 귀 사무소에 세무 대행을 위임한다는 서면 증빙
5. **저장** → 시스템이 자동으로 두 가지를 수행:
   - `customer` 레코드 생성 (`customer.user_id`는 비워둘 수 있음 — Phase B-2에서 null 허용으로 변경됨)
   - `customer_consultant` 조인 레코드 생성 — 귀 사무소의 대표 컨설턴트 또는 로그인 사용자가 자동 배정됨
6. 필요 시 **추가 컨설턴트 배정** — 같은 사무소의 다른 직원을 이 고객에게 co-consultant로 추가 가능

**핵심**: 고객 데이터는 **RLS 정책**에 의해 자동 격리됩니다. JTC 세무사나 다른 외부 사무소는 이 고객을 절대 볼 수 없습니다. `get_consultant_tax_partner_id()` 함수가 모든 SELECT에 자동 적용됩니다.

### 4.2. 플로우 B — 이번 달 고객사 PPN 신고 대행

1. 사이드바 **고객** → 해당 고객 선택
2. 고객 상세 페이지에서 **월 신고 → PPN** 진입
3. 신고 기간 선택 (예: 2026년 3월)
4. **인보이스 캡처** 탭에서 고객이 보내준 Faktur Pajak 이미지를 일괄 업로드
5. OCR 결과 검토 → 매출/매입 분류 수정 → **자동 계산** 실행
6. **제출** → JTC 운영팀 큐로 이동 (`djp_submission_queue`)
7. 운영팀이 검토·승인·eBilling 발행·DJP 제출까지 순차 처리
8. 완료되면 귀 사무소 대시보드에 상태가 `COMPLETED` 로 바뀌며 BPE(접수증) PDF가 자동 저장됨

### 4.3. 플로우 C — 여러 고객의 PPh21 일괄 처리 (Growth 이상)

1. 사이드바 **세무 관리 → 일괄 PPh21**
2. 처리할 고객 체크박스로 여러 건 선택
3. 공통 신고 기간 선택
4. 엑셀 템플릿 다운로드 → 고객별 급여 데이터 입력 → 업로드
5. 시스템이 고객별로 개별 PPh21 계산을 실행하고 오류를 표로 보여줌
6. 오류 0건이면 **전체 제출**
7. 이 기능은 **Growth 플랜 이상**에서만 활성화됩니다. Starter는 개별 고객 화면에서 1건씩 처리해야 합니다.

### 4.4. 플로우 D — Tier 업그레이드

고객이 늘어 Tier 한도에 근접하면 사이드바 **청구 → 컨설턴트 플랜** 에 경고 배지가 뜹니다.

1. 원하는 상위 Tier 카드 → **업그레이드**
2. Midtrans 결제 → 결제 완료 시 웹훅(`CONS-*`)이 자동으로 기존 구독을 `SUPERSEDED`, 신규 구독을 `ACTIVE` 로 전환
3. 해제 즉시 새 한도가 적용되어 추가 고객 등록과 일괄 기능이 열립니다

## 5. Tier 요금제 상세

**모든 Tier는 월 구독, VAT 11% 별도**. Midtrans 결제, 결제 주기는 30일.

| Tier | 월 요금 | 관리 가능 고객 수 | 핵심 기능 | 적합 대상 |
|---|---|---|---|---|
| **Starter** | Rp 1,000,000 | 최대 10명 | 기본 월·연 신고, OCR, Accurate·Jurnal 연동 | 1인 사무소, 소규모 고객 포트폴리오 |
| **Growth** | Rp 3,000,000 | 최대 50명 | Starter 기능 + **일괄 PPh21**, **팀 초대**, **월 통합 대시보드**, 대량 업로드 | 2~5명 사무소, 성장 단계 |
| **Enterprise** | Rp 8,000,000 | 사실상 무제한 (`max_clients >= 999_999`) | Growth 기능 + **전담 JTC 서포트**, 맞춤 API, 이전가격(TP) 컨설팅 지원 | 10명 이상 대형 사무소 |

### 5.1. Tier 추천 엔진
사이드바 위젯은 현재 귀 사무소의 활성 고객 수를 자동 집계하고, `suggestConsultantTier(clientCount)` 함수로 권장 Tier를 보여줍니다.

- **0~10명** → Starter
- **11~50명** → Growth
- **51명 이상** → Enterprise

### 5.2. 다운그레이드
현재 고객 수가 낮은 Tier 한도 이내일 때만 다운그레이드 가능합니다. 초과 상태에서는 버튼이 비활성화됩니다.

### 5.3. 결제 실패 시
Midtrans 결제가 실패하면 구독이 `CANCELED` 상태로 되며, 다음 결제 주기까지 **신규 고객 추가와 신고 제출이 차단**됩니다. 대시보드 상단에 즉시 경고 배너가 뜹니다.

## 6. 팀 관리 (Growth 이상)

사무소에 직원이 여러 명이라면 **팀 관리** 메뉴에서 초대합니다.

1. **팀 관리 → 직원 초대**
2. 이메일 주소 입력 → 역할 선택 (사무소 컨설턴트)
3. 초대 메일 발송 → 직원이 링크 클릭 → 비밀번호 설정
4. 자동으로 `consultant` 레코드가 해당 사무소(`tax_partner_id`)에 연결됨
5. 이제 그 직원은 사무소의 고객에 접근 가능 (`customer_consultant` 배정 필요)

비활성화된 직원은 더 이상 로그인할 수 없고, 해당 직원이 담당하던 고객은 자동으로 대표 컨설턴트 목록에 노출됩니다.

## 7. 고객과 AI Pajak의 관계

구조 이해를 위한 중요한 점:

- **귀 사무소의 고객은 JTC의 고객이 아닙니다.** JTC는 귀 사무소에 도구만 제공할 뿐 고객 청구나 소통에 관여하지 않습니다.
- **신고 제출 단계**에서는 JTC 운영팀(`TAX_OPERATOR`, `SUPERVISOR`)이 큐를 처리합니다. 이 과정에서 운영팀은 제출 건의 메타데이터(고객 이름, 신고 유형, 금액)는 보지만 고객에 대한 상세 영업 정보에는 접근하지 않습니다.
- **고객은 AI Pajak에 직접 가입하지 않습니다.** 귀 사무소가 대신 등록합니다. 고객이 자체 로그인을 원한다면 선택적으로 초대할 수 있습니다.

## 8. 문서·증빙·POA

### 8.1. POA (Power of Attorney) 관리
귀 사무소가 대행하는 **모든 고객마다 POA가 필요**합니다. 고객이 자사 대표 명의로 서명·스캔한 위임장을 귀 사무소가 업로드합니다.

- 고객 상세 페이지 → **POA 탭 → 업로드**
- 유효 기간 입력
- 만료 30일 전 자동 알림

### 8.2. 회계 연동 (고객 단위)
Accurate, Mekari Jurnal, Open Banking 연동은 **고객별로 각각 설정**됩니다. 고객 상세 페이지 → **통합설정** 탭 → 연결. OAuth 토큰은 해당 고객 레코드에만 귀속되며 다른 고객이나 사무소에서 접근할 수 없습니다.

## 9. 자주 묻는 질문

**Q. 구독료는 어떻게 청구되나요?**
A. 사무소 대표 계정 이메일로 Midtrans 결제 요청이 매월 발송됩니다. 지불은 사무소 명의 계좌·카드·전자지갑으로 합니다.

**Q. 고객에게 직접 청구하려면?**
A. 현재는 귀 사무소가 고객에게 **별도 인보이스**(귀 사무소 양식)를 발행합니다. AI Pajak 내부에서 고객을 향한 직접 청구 기능은 향후 제공 예정입니다.

**Q. JTC 세무사가 우리 고객 정보를 볼 수 있나요?**
A. **볼 수 없습니다.** RLS 정책에서 `tax_partner_id` 기준으로 엄격히 분리됩니다. 다만 신고 제출 시 운영팀이 제출 건 메타데이터(이름·NPWP·금액·신고 유형)를 처리합니다. 이건 DJP 제출을 위한 필수 단계입니다.

**Q. 한 달에 Enterprise Rp8M은 너무 큽니다. 협상 가능한가요?**
A. Enterprise 이상이 필요하거나 커스텀 요건(전담 매니저, SLA 등)이 있다면 JTC **마스터 담당자**에게 연락하여 **맞춤 견적(Custom Pricing Quote)**을 요청하세요. 사이드바에서 "맞춤 견적 요청" 버튼 또는 이메일로 문의 가능합니다.

**Q. 중간에 다른 사무소로 고객 이관이 필요하면?**
A. 현재는 수작업입니다. JTC 지원팀에 이관 요청서를 보내면 마이그레이션을 도와드립니다.

**Q. Tier를 결제 안 하면 어떻게 되나요?**
A. 구독이 만료되면 읽기 전용 상태로 전환되며, 기존 데이터 조회는 가능하나 신규 신고 제출이 불가능합니다. 60일 경과 시 데이터는 아카이빙됩니다.

## 10. 주요 용어

| 용어 | 뜻 |
|---|---|
| **tax_partner** | 플랫폼 DB상의 세무 사무소 엔티티. `partner_type`이 `JTC` 또는 `EXTERNAL` |
| **EXTERNAL** | JTC가 아닌 외부 사무소. 귀 사무소의 유형 |
| **consultant** | 사무소 소속 직원 (컨설턴트 1명 = 1 유저) |
| **customer_consultant** | 고객-컨설턴트 배정 관계 테이블 |
| **tax_partner_subscription** | 사무소의 Tier 구독 레코드 |
| **CONS-** | 컨설턴트 구독 Midtrans 주문 ID 접두사 |
| **POA** | 위임장 (Power of Attorney) — 고객이 사무소에 세무 대행을 위임하는 문서 |
| **RLS** | Row Level Security — DB 행 단위 접근 제어. 고객 격리의 기술적 근간 |
