# 통합 아키텍처 문서

## 개요

AI Pajak는 2개의 파트(API, Web)로 구성된 모노레포입니다. 이 문서는 파트 간 통합 방법을 설명합니다.

## 통합 포인트

### 1. Web → API (REST)

| 소스 | 타겟 | 방식 | 설명 |
|------|------|------|------|
| `apps/web` | `apps/api` | REST API | Vite 프록시 경유 |

**프록시 설정** (vite.config.ts):

```typescript
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:3000',
      changeOrigin: true,
    },
  },
}
```

**API 클라이언트** (apps/web/src/api/client.ts):

```typescript
const client = axios.create({
  baseURL: '/api',
});
```

### 2. API → Database (Prisma)

| 소스 | 타겟 | 방식 | 설명 |
|------|------|------|------|
| `apps/api` | PostgreSQL | Prisma ORM | 중앙화된 레포지토리 |

**연결 설정**:

```env
DATABASE_URL="postgresql://user:password@localhost:5432/ai_pajak?schema=public"
```

### 3. API → PaddleOCR (OCR 서비스)

| 소스 | 타겟 | 방식 | 설명 |
|------|------|------|------|
| `apps/api` | PaddleOCR Service | HTTP/gRPC | 문서 OCR 처리 |

**구현 예정**: Python 기반 PaddleOCR 서비스 (별도 컨테이너)

> **마이그레이션**: Gemini API → PaddleOCR 전환 예정

## 데이터 흐름

### 세금 케이스 워크플로우

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│   Web   │────▶│   API   │────▶│   DB    │
│(Upload) │     │(Process)│     │ (Save)  │
└─────────┘     └─────────┘     └─────────┘
                     │
                     │ OCR Request
                     ▼
              ┌───────────┐
              │ PaddleOCR │
              │ (Python)  │
              └───────────┘
```

1. **Upload**: 사용자가 Web에서 세금 문서 업로드
2. **OCR**: PaddleOCR 서비스에서 문서 텍스트 추출
3. **Process**: API가 추출된 데이터 처리 및 저장
4. **Human Review**: 컨설턴트 리뷰
5. **Filing**: DJP로 세금 신고

## 향후 통합 계획

### 1. DJP API 통합

인도네시아 세무국 API 연동:

```
apps/api/src/djp/
├── djp.module.ts
├── djp.service.ts
└── dto/
```

### 2. 인증/인가

JWT 또는 세션 기반 인증 구현:

```
apps/api/src/auth/
├── auth.module.ts
├── auth.service.ts
├── jwt.strategy.ts
└── guards/
```

모노레포 내 공유 패키지:

```
packages/
└── shared/
    ├── types/
    └── utils/
```
